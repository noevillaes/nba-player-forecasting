    How it works

    Every morning a scheduled job downloads the NBA schedule, rosters and the previous night's box scores, forecasts that day's games and scores yesterday's forecasts against what actually happened. The results are committed to GitHub before tip-off, so every forecast on this site has a public timestamp and can't be changed after the game.

    Player forecasts

    For every player on each roster, a LightGBM model forecasts 16 box-score stats. It's trained with quantile loss at the 10th, 50th and 90th percentiles: the 50th is the forecast, and the other two form the 80% range.

    The model sees each player's recent form at several speeds: averages over his last 3, 5, 10 and 20 games, smoothed averages that fade older games gradually, and per-minute production over the last 82 games. Short windows catch role changes within days, like a starter moved to the bench, and long ones keep a hot or cold streak from being taken at face value. All of them only use games played before the one being forecast.

    Player forecasts are then reconciled with the team-score forecast. Without this step, a roster full of scorers can add up to a total no team would reach. The multiplier shown above each box score is that adjustment.

    Ranges that stay honest

    The ranges are calibrated with conformalized quantile regression, so about 8 in 10 actual values should land inside them. At the start of the season the calibration uses the previous season. Then, once a week, it's redone with the last 28 days of live forecasts, which the model never saw, so the ranges adapt if this season is more or less predictable than the last one.

    A model that learns during the season

    Once a month a challenger model is trained with everything up to two weeks ago, this season included. Both models then forecast those last two weeks, which neither has seen. The challenger only takes over if it makes less error. Each forecast records which version made it, so the track record stays honest.

    Game forecasts

    Team scores come from a structural formula: expected pace times each team's offensive and defensive efficiency, plus home-court advantage. In validation it beat a gradient-boosted model. Win probabilities are calibrated with Platt scaling, and a Brier score of 0.25 is what a coin flip would get.

    What it's compared against

    Every player stat is compared with that player's average over his last 10 games, a simple forecast that's hard to beat. The improvement column shows how much less error the model makes than that average.

      Known limits

      • There's no availability model, so players who end up not playing still get a forecast. They show as DNP and aren't counted in the errors.
      • Individual matchups aren't modeled.
      • Rookies without NBA games have no history to forecast from.

      Data

      Historical box scores from the Kaggle dataset Historical NBA Data and Player Box Scores (1947 to present) and live data from the NBA stats API through nba_api. The "Backtest" set holds forecasts for March 2026 games, made after the fact to test the whole pipeline before the season started.

      Every morning

      A scheduled task runs the whole pipeline before the first game of the day.

      1. Pull new dataSchedule, rosters and last night's box scores from the NBA stats API.
      2. Build featuresRolling player and team features from every game played so far.
      3. Recalibrate rangesOnce a week, with the last 28 days of live errors.
      4. Forecast players16 stats per player with 80% ranges, reconciled with the team scores.
      5. Forecast gamesTeam scores, total, margin and win probability.
      6. Score yesterdayYesterday's forecasts are compared with the real box scores.
      7. PublishEverything is committed to GitHub and this site rebuilds a couple of minutes later.
      8. RetrainOnce a month, a challenger model trained with this season's games. It only replaces the current one if it wins.
